# Notemaker Vault (sensitive data) — format v1

The vault stores sensitive items encrypted with keys that are **held in hardware**:
the Secure Enclave on a Mac, or a passkey (Touch ID / security key) in the browser.
No key, passcode or recovery key is ever stored in `data.json`, localStorage, exports
or any server. Both apps implement this spec exactly; `docs/vault-test-vector.json`
(generated by `docs/gen-vault-vector.js` with WebCrypto) must pass in both.

## Key hierarchy
```
Vault Data Key (VDK, 32 random bytes, exists only in memory while unlocked)
 ├─ encrypts every item and blob (AES-256-GCM)
 └─ is wrapped by 1..n keyslots, each opened by a hardware secret:
     • secure-enclave  (macOS)  P-256 key generated in the Secure Enclave, Touch ID / password to use
     • passkey-prf     (web)    WebAuthn passkey PRF output (Touch ID / security key)
     • recovery        (opt.)   printable recovery key the user stores offline
```
Vault modes chosen at setup: `"hardware-only"` (no recovery slot) or `"hardware+recovery"`.

## Storage (top-level `vault` field of the v2 document)
```jsonc
"vault": null | {
  "version": 1,
  "createdAt": ISO,
  "mode": "hardware-only" | "hardware+recovery",
  "verifier": { "iv": b64(12), "ct": b64 },        // AES-GCM(VDK, iv, "notemaker-vault-ok", aad "notemaker/vault/v1/verifier")
  "keyslots": [Keyslot],
  "items": [ { "id": UUID, "iv": b64(12), "ct": b64, "createdAt": ISO, "updatedAt": ISO } ],
  "blobs": { "<blobId>": { "iv": b64(12), "ct": b64 } }   // ONLY inside exported backups; see Files
}
```
Item titles and types are inside `ct`: a locked vault reveals only the number of items.

## Keyslot
Common: `{ "id": UUID, "type": "...", "label": string, "createdAt": ISO, "iv": b64(12), "ct": b64(48) }`
where `ct` = AES-GCM(wrapKey, iv, VDK) with AAD = UTF-8 `"notemaker/vault/v1/slot/" + id`.
`wrapKey` = HKDF-SHA256(IKM, salt, info, 32 bytes):

| type | extra fields | IKM | salt | info |
|---|---|---|---|---|
| `recovery` | `salt` b64(16) | the 32 recovery-key bytes | `salt` | `"notemaker/vault/v1/recovery"` |
| `secure-enclave` | `ephemeralPublicKey` b64 (X9.63, 65 bytes), `publicKey` b64 (SE key, X9.63), `device` string | ECDH(SE private key, ephemeral public key) shared secret (32 bytes) | `ephemeralPublicKey` raw bytes | `"notemaker/vault/v1/secure-enclave"` |
| `passkey-prf` | `credentialId` b64url, `rpId` string, `prfSalt` b64(32), `salt` b64(16) | PRF output for input `prfSalt` (first PRF eval, 32 bytes) | `salt` | `"notemaker/vault/v1/passkey-prf"` |

**Secure Enclave slot (macOS):** create `SecureEnclave.P256.KeyAgreement.PrivateKey` with access control
`[.privateKeyUsage, .userPresence]` (Touch ID or Mac password on every unlock). To wrap: generate an
ephemeral software P-256 key, ECDH with the SE public key, derive wrapKey, encrypt the VDK. Store the SE key's
`dataRepresentation` (an opaque handle encrypted by the Secure Enclave, useless on any other Mac) in the
**macOS Keychain** (generic password, service `com.mth.notemaker.vault`, account = slot id) — never in
`data.json` or exports. To unwrap: load the handle, `sharedSecretFromKeyAgreement(with: ephemeralPublicKey)`.

**Passkey slot (web):** `navigator.credentials.create({publicKey: {..., authenticatorSelection: {userVerification: "required", residentKey: "preferred"}, extensions: {prf: {eval: {first: prfSalt}}}}})`;
if the result has no PRF output, call `get()` with the same extension. Each unlock: `navigator.credentials.get({publicKey:{allowCredentials:[{id}], userVerification:"required", extensions:{prf:{eval:{first: prfSalt}}}}})`.
Requires a secure context (`https://` or `http://localhost`) and a PRF-capable authenticator (Safari 18+, Chrome 116+
with iCloud Keychain / platform passkeys or a FIDO2 key). If PRF is unavailable, say so clearly; never fall back to
storing a key in the browser.

## Recovery key
32 random bytes → append the first 2 bytes of SHA-256(those 32 bytes) → 34 bytes → Crockford Base32
(alphabet `0123456789ABCDEFGHJKMNPQRSTVWXYZ`, MSB-first, last group zero-padded) → 55 characters, shown as
11 groups of 5 joined with `-`. Parsing: uppercase, drop spaces and `-`, map `O→0`, `I/L→1`, decode, verify checksum.
Shown once at setup (with copy/print/save-as-text); the app keeps no copy.

## Items (decrypted payload JSON, AAD = UTF-8 item id)
Common: `{ "type", "title", "favorite": bool, "notes": string, "tags": [string] }` plus:

| type | fields |
|---|---|
| `note` | `markdown` |
| `login` | `username`, `password`, `url`, `totpSecret` (optional, may be "") |
| `card` | `kind` (`"card" \| "id" \| "license" \| "other"`), `holder`, `number`, `expiry`, `cvv`, `issuer`, `fields: [{label, value, secret: bool}]` |
| `file` | `fileName`, `mime`, `size` (bytes), `blobId` (UUID), `sha256` (hex of the plaintext file) |

## Files
File bytes are encrypted separately: AES-GCM(VDK, iv, bytes, AAD = UTF-8 `"blob:" + blobId`), max 25 MB per file.
Stored locally outside the main document — macOS: `~/Library/Application Support/Notemaker/vault-blobs/<blobId>.bin`
(= iv ‖ ct); web: IndexedDB database `notemaker-vault`, store `blobs`, `{id, iv, ct}`. Exported backups include
them in `vault.blobs` (base64). Deleting an item deletes its blob.

## Behaviour (both apps)
- Unlock: pick an available slot for this device (Touch ID / passkey), or "Use recovery key".
- Unlocking on a device without its own hardware slot (e.g. after import via recovery key) offers
  "Add this Mac / this browser" which creates a new hardware slot. The last slot can't be removed.
  In `hardware-only` mode no recovery slot exists, so another device can never open the vault (by design).
- Auto-lock after `settings.vaultAutoLockMinutes` (default 5) of inactivity, on sleep/screen lock (macOS),
  when the page is hidden longer than that (web), and on quit. The VDK is wiped from memory on lock.
- Secrets are masked until revealed; copying a secret clears the clipboard after 30 s if unchanged.
- Password generator: length 8–64, upper/lower/digits/symbols toggles, avoid look-alikes; strength meter.
- Vault content never appears in global search, backlinks, Markdown export, insights or the command palette
  (the palette may only offer "Open vault" / "Lock vault").
- Changing items: re-encrypt the item with a fresh IV every save. Rotating isn't required for v1.
- `settings` gains `"vaultAutoLockMinutes": 5`.
